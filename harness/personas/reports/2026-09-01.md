## NEW issue (the headline)

### NEW-1. CONFIRMED — Duplicate-dropper collapses legitimate multi-scheme programming (S1, regression from the #3 fix, Frank)

> Frank: "That first 'heavy-feeling' set at 70% for 5 reps? Not powerlifting
> style… Felt like babysitting a hard warm-up, not actual strength work."

Evidence: Frank asked for "percentages and top sets". The model answered with
a percent ramp expressed as several `Barbell back squat` entries (different
reps each); the new `sanitizeRoutine` dupe rule kept only the first. His
delivered squat day is **one exercise, 1 set × "5 @ 70% 1RM"** whose own tip
still says *"Rest 3-4 minutes after this set before next work set"* — a next
work set that was just deleted. Backend log: 4× `[sanitize] dropped duplicate
exercise "Barbell back squat"` on generate, another on revise (the revise
reply promises "backoff sets… fives at ~80%" that likewise never survive), and
`[time-budget] limit 90 min, estimate 9.8 min` — a 90-minute request shipped
as ~10 minutes of work, unflagged because only *over*-limit trips a check.
**Engineering read:** entry-level dedupe is the wrong grain. Strength
programming legitimately lists one lift under multiple schemes (top single +
backoffs + pause work). Merge same-name entries by summing sets / keeping
per-scheme rep text, or only drop a duplicate whose reps/notes match too; and
add an under-duration sanity check (est. < ~40% of the stated limit is as
suspicious as over). Dana's original dupe ("second lighter round" of Seated
Leg Curl) would be correctly *merged* by that rule, not dropped.
